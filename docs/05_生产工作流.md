# 1. Source of Truth

唯一权威基线：

> **GitHub `amisheng77/SHWZ-V4` live `main` + `SHWZ_Current_Context.md`**，并依当前六文档 owner 与 Y4 地理事实登记读取；旧仓库 `amisheng77/SHWZ` 非本项目当前 SoT。

信息分为三类：

### Canon
作者已确认并写入当前Git基线。

### Proposal
候选方案**无论是否已提交 Git**，只要未明确经作者批准、按 owner 迁移成 Canon，就**不能自动当成事实**。Proposal V1.3 的已获批准**制度原则**已按 owner 迁移；其中标注〔P〕的候选事件仍是 Proposal，不因文件存在于 Git 而转正。

### Replaced / Abandoned
已经被新版或作者明确替代，不得因“看起来合理”重新恢复。

若模型记忆、旧聊天、旧文档与live main冲突：

> **live main优先。**

# 2. 四种事实必须分开

正文创作时严格区分：

1. **Author Truth**：作者层面真实情况；
2. **Story Fact**：正文中确实已经发生；
3. **Character Belief**：某个角色相信/怀疑的版本；
4. **Historical Record**：后世档案、官方史、民间传说中的版本。

尤其暗线事件不能把“角色怀疑”自动升级为“作者真相”。

# 3. 写前流程

每一章正式写作前：

1. 读取 `SHWZ_Current_Context.md`；
2. 读取当前 `SHWZ_Story_State.md`；
3. 读取本章对应POV档案；
4. 读取本章所在时间线范围；
5. 读取直接相关专题；
6. 读取 `docs/05_生产工作流.md` 中与本章有关的伏笔；
7. **素材打捞**：按合同"素材引用"栏从 `research/` 素材库取 ≤3 条机制，蒸馏为素材卡（进 pack v2 的 Doc A）——不整库进上下文；
8. 创建 Chapter Contract；
9. 通过 Anti-Hallucination Gate 后再写正文。

不需要每章把全部世界观塞入上下文。

原则：

> **只读取本章需要的Canon，但一定先读。**

# 4. Chapter Contract

每章开写前至少锁定：

- 章节编号/暂名；
- 时间；
- 地点；
- POV；
- 本章开始状态；
- 本章必须发生；
- 本章不能发生；
- 本章人物知道什么；
- 本章人物不知道什么；
- 本章至少推进的两项功能；
- 人物弧变化；
- 需要埋/回收的伏笔；
- 本章存在理由。

**素材三层嵌入法**（素材引用栏的使用规则）：

| 层级 | 借什么 | 形态 | 例 |
|---|---|---|---|
| **场景层**（最常用） | 礼制、器物、流程、行话 | 直接构成场景质感——让读者**闻到**战国 | 学宫辩难如何立题、门客分几等餐食、使者如何呈国书 |
| **机制层** | 权力与人的反应模式 | 化入**原创人物的原创决策** | "冯谖市义"的机制→渤的周急养望（已入 Bible）；"二柄"的恐惧→青王忌渤 |
| **反用层**（最高级） | 读者的历史预期 | 借预期当背景板，前景走原创 | 铎有信陵君式社交人格，献城时刻的抉择却反门客逻辑 |

铁律：**拆机制，不抄桥段。**判据（换皮可辨认度测试）：换掉国名人名后读者仍能认出"这是某典故"＝抄，重写。素材库文言原文不得直接进正文（古代语境翻译门同样适用于素材）。

# 4.5 Pack 结构规范 v2（三文件分工，2026-09-26）

> 病灶（CH011 pack 实测 1600+ 行）：单文档巨无霸；指令/数据/参考无分工；**未做知识边界过滤**（含人物终局与未来弧——剧透即 foreshadow 漂移源）；canon 散文整段复制、检索成本高。
> 对标 analyzerpro step1：每章必读 3 文件、强制顺序、数据结构化。

**每章 pack 拆为三个分工文档，写手按序读取：**

| 文档 | 内容 | 弹性预算（行） | 性质 |
|---|---|---|---|
| **Doc A 写作手册** | 本章存在理由＋必须/不能发生＋Voice Card＋素材卡＋禁忌词表（global forbidden words 展开＋本章专属）＋结尾要求。由合同**蒸馏**生成（去状态记录类字段），不是合同复制 | 60—260（通读装脑，必须精） | **写手通读、全部装脑**——写作中不再回看也可以 |
| **Doc B 设定卡** | 本章出场人物**截至本章**的状态/关系/行为模式＋场景地理、礼制、器物事实＋知识边界表。从 03/06/08/02 按**合同知识边界节过滤**抽取，结构化列表而非散文摘录 | 120—700（重人物/大会章自然偏长；超上限才告警） | 备查——写作中按需检索 |
| **Doc C 专名与前情** | 本章专名表（registry 摘录＋称谓规则）＋前章 Delta＋相关伏笔 2—3 行 | 60—350 | 写作中随手查 |

> 预算由引擎 `PACK_BUDGETS` 常量单一源控制（区间内 ✓、仅超上限告警）；特殊章型调常量，不写死在流程里。

**知识边界过滤器（本规范的核心铁律）**：晚于本章时间点的一切 Author Truth（人物终局、未来弧、暗线真相、跨年代反讽）**不得进入任何 Doc**。终局信息只属于 00—14 原档与审计层。

**分工红利**：写手读蒸馏档，审计读原档——L0 用合同全文、L1/L2 用 canon 原档对照。**写手上下文干净，审计基准完整**，两头互不妥协。

**执行路径**：CH012 起以本规范手工编译三文件试点（pre-engine pack 照此）；格式经 CH012—013 验证后，固化进 nc 引擎（pack schema v2）。

若“本章存在理由”无法用1—2句话说清：

> **先不写。**

# 5. Anti-Hallucination Gate

开写前检查：

1. 是否新增了没有来源的国家/制度事实？
2. 是否新增了没有确认的亲属关系？
3. 是否让人物知道了不该知道的信息？
4. 是否把Proposal写成Canon？
5. 是否为了方便剧情违反神异/乌金/地理/制度规则？
6. 是否让非POV人物突然被全知读心？
7. 是否把人物后期性格倒灌到青年时期？
8. 是否将**后期南粮北运需求**倒灌成 Y5—7 青沧开战动机，或将**竹山岛／岱山岛、湄／峤、荆三水系**混置？
9. 是否把杜若商号货权误写成渤府属官，或把雍工正误写成仲符官职、兼管国尉军令和相国财粮？
10. **D84—D88 人物／神异检查**：麒麟是否被仁德远程召来、续命救人、直接杀兽、反复出现在终战？核心女萨巫是否被写成全知仁慈／能役兽？舟月是否被写成“航正自然有军权”或 Y7 即全国海军司令？终楠是遭贬才退役，还是第一线负伤后主动退出？骥在储位竞争前是否已有荆国宗室正妻？

任何一项“是”，先回查Canon。

# 6. 单章写后 Continuity Audit

至少检查**十二类**（第 11 项为 V1.3 政治经济专项，第 12 项为 D84—D88 神异／婚配／军职／成就回报）：

1. **时间**：年份、季节、年龄；
2. **地理**：所在地、行程、交通耗时；
3. **知识边界**：谁知道什么；
4. **人物状态**：官职、伤势、关系、心理阶段；
5. **物件连续性**：信、印、乌金、船、档案等；
6. **制度连续性**：制度是否提前出现或倒灌；
7. **神异边界**：灵兽/巫者能力是否越界；
8. **POV纪律**：是否泄露非POV内心；诸子称谓校验（D36 修订：正文不以『法家／儒家／道家／墨家』给人物贴派别标签；『墨者』仅在必要的师承／守城／守鸾场景中偶尔出现，不写成掌门教团；法儒道经人物言行显形；青鸾自择且不限墨者）；
9. **人物弧**：是推进一步，还是突然跳级；
10. **素材嵌入**：拆机制不抄桥段（换皮可辨认度测试）；素材库文言原文未直接进正文。
11. **政治经济 Gate（§18）**：事发年份是否允许制度／矿区与港路存在，土地和货权归属是否正确，粮／器／乌金能否追到真实交割人，明面凭证与实际到货是否分离、杜若／渤各自网络边界是否保持。无相关物件的章不得为满足 Gate 生造经济戏。
12. **角色／神异 Gate（§19）**：麒麟生态感知与偶遇非仁德触发、萨巫性别及道德灰度、舟月航正／将军任职分期、终楠受嘉奖而因伤病退役、骥的荆国宗室正妻在储位争夺前已婚、已婚贵族未出场之配偶不得自动删除。

# 7. Chapter Delta

每章定稿后，不只保存正文，还要记录“这一章改变了什么”。

至少包含：
- 时间推进；
- 人物位置/身份变化；
- 伤势与资源变化；
- 关系变化；
- 谁新知道了什么；
- 哪个秘密被隐藏/误解；
- 新增物件；
- 新增伏笔；
- 已回收伏笔；
- 需要同步到Story State的内容。

下一章优先读取Delta和Story State，而不是反复把全部旧正文重新塞入上下文。

# 8. Story State

`SHWZ_Story_State.md`回答：

> **故事现在进行到哪里。**

它不是世界观百科。

它保存：
- 当前章节；
- 当前年份/季节；
- 主要人物当前状态；
- 主要国家当前政治状态；
- 核心秘密知识矩阵；
- 当前活跃冲突；
- 最近三至五章产生的关键Delta。

---

# 9. Continuity Ledger

用于管理：
- 人物年龄、身份、官职、位置；
- 伤势；
- 已知秘密；
- 关系变化；
- 关键物件；
- 制度启用时间；
- 行程；
- 文本伏笔；
- 诗稿、史稿不同版本。

这是小说数据库，不承担文学表达。

---

# 10. Open Threads

所有未解决伏笔必须有状态：

- 首次出现；
- 当前谁知道；
- 当前读者知道多少；
- 预计回收阶段；
- 是否必须回收；
- 是否允许永久模糊。

避免长篇写作中丢失伏笔。

---

# 11. Voice Card

主要POV维护短Voice Card。

它不规定“不同文风”，而规定：
- 角色首先注意什么；
- 什么东西他通常不会注意；
- 比喻来源；
- 思考习惯；
- 常见误判；
- 语言节奏。

用于防止不同POV声音串台。

# 13. 作者与ChatGPT的分工

ChatGPT优先负责：
- 初稿；
- 结构展开；
- 年龄/时间/知识边界检查；
- 文档同步；
- 伏笔台账；
- 版本一致性；
- 章节压缩建议。

作者优先负责：
- 人物是否“对”；
- 情绪是否成立；
- 哪个选择更有戏剧性；
- 是否套路；
- 是否过度解释；
- 最终Canon确认。

总结：

> **模型负责continuity，作者负责judgment。**

最终决定权始终在作者。

# 15. Canon变更流程

作者提出修改后先判断：

### 局部文字修改
只改正文。

### Canon修改
必须：
1. 修改对应Bible；
2. 修改Story State；
3. 检查受影响旧章；
4. 必要时修改Open Threads/Ledger；
5. Git commit说明变更理由。

不能只改正文而留下设定文件旧值。

# 17. 正式逐章创作前的三项前置Gate

在稳定进入逐章生产前，必须优先完成三项小说化验证。

## Gate 1：关键场景压力测试

目的：

> **验证小说是否真的“活”。**

使用约6—8个代表性场景检查：
- 人物生命感；
- POV声音；
- 阅读动力；
- 三层文本自然度。

**当前状态：已锁定，但按作者指示稍后开展，暂不执行。**

## Gate 2：Character Humanization Pass

所有核心人物必须补足：
- 私人欲望；
- 羞耻/弱点；
- 不理性偏爱；
- 嫉妒/恐惧/虚荣；
- 无剧情功能的快乐；
- 至少一次违背长期逻辑但符合人性的选择。

目的：

> **避免“设计正确的人物”变成主题棋子。**

## Gate 3：核心故事单元与章节骨架

先把约25年历史压成核心故事单元，再拆为约88章；当前骨架见 07_章节骨架.md。

每个故事单元必须回答：

1. 谁想做成什么？
2. 什么具体事件阻止他？
3. 哪个POV最适合？
4. 谁发生不可逆变化？
5. 删掉后全书损失什么？

只有通过这五问的历史节点，才优先获得正文展开资格。

# 18. 政治经济连续性 Gate（作者批准 V1.3 制度迁移，作为写前／写后通用规则）

> **分层基准**：00 §10.1 是创作原则；01 §1.1 是时代经济因果；02 §十·一／十·二 是国家制度及地理所有权；03 §2.1.1 是杜若独立经营人格；04 §0.9 是章节主题叠加层；Y4 图上权属详见 docs/maps/Y4_全域地理事实登记_V1.md。V1.3 中标〔P〕的案例、船型、费用与台词**不是已锁事实**。

以下任一项在该章实际涉及经济物件、土地权属、国家财政或跨国运送时须回答；不涉及则标 **N/A**，不要为了“验收全绿”创造无戏剧功能的商账。

| 检查 | 必填的可追溯事实 | 硬误差示例 |
|---|---|---|
| **时间与旧账** | Y0—4 传统防草原／兽患增量／Y10—12 真盟共同防务发生在哪一期？债属于国府、商号还是援助？ | 把 Y-11 终楠父家旧人战债写成联盟兽债；把 Y5 青沧战争写成 Y20 南粮救荒 |
| **主权／城属** | 城镇、港口、矿脉、部落属于哪个政治单位及该年是否已经更易主？ | 北𬩽 Y4 独立赴会；峤国沿海竹山岛；云阳君统治顺州王室港 |
| **货物／权益** | 谁发现矿、掌矿性与祖地？谁同意采、谁炉炼、谁承运、谁设价和受验？ | 一张矿券自动购买山濮所有祖地；“渤的乌金矿”取代部落和荆封君 |

7. **狍鸮反讽**：后世认为Y4最重要的是御兽，当时很多人真正关心的却是继承、名望、学宫、盟约、婚姻和人脉。
