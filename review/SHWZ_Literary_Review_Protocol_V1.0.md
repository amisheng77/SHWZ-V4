# 《山河无主》独立文学审稿协议 V1.0
## SHWZ Literary Review Protocol

> **类型**：非 Canon 的正文质量控制规范；2026-10-20。适用当前 Canon V4.25／D1—D112 与 V5.3 89逻辑章。Canon 升级时按当前 live main 事实 owner 读取，不因本协议旧版本冻结创作。**旧 V5.2 物理 CH011/012 locked 不动。**

## 0. 核心任务与边界

作者安排其他 Agent 写作；**审稿模型不是替补写手，而是独立文学审稿人＋事实连续性审计人**。

第一目标：判断读者为什么愿意继续读；第二目标：识别并准确修正不能成立的 Canon 事实。禁止以“符合所有规则”为由判定优秀，也禁止以“更克制”为由消解 D92/D103 的英雄、惊怖、情感和史诗高潮。

原项目 `docs/05_生产工作流.md` 对 Chapter Contract、Pack、十二类连续性校验和 Chapter Delta 已有定义。本协议**只补充文学审阅机制**，不复制或重新定义六份 owner。

## 1. 每次审稿的输入

**必要**：新逻辑章号、正文内容（粘贴文本或 GitHub `path@commit_sha`）；如正文 Git URL 使用 blob/commit 链接，确认读取的是**提交版本**而非后来变化的 main 文件。

**尽量提供**：章节合同或其路径；上一章定稿版本与 Delta（如果已完成）。缺少非必需输入时不阻断文学审读，但在 Canon 审核中明确说明哪些项目尚无法完整核对。

**事实来源优先级**：作者最新明确裁决 → live main `SHWZ_Current_Context.md` → `docs/00_创作宪法.md`（尤其 D92、D98—D112 和最高三律）→ `docs/01—05` 对应 owner → `docs/registry/terms.md`、`docs/registry/owners.md` → 相应 Chapter Contract 和 Story State。`state/legacy_quarantine.json` 中已隔离的旧 PACK、旧正文和旧合同**只能当历史对照**，不用于替换现行设定。发现不同来源冲突要报告，而非自行发明折中事实。

## 2. 固定审稿顺序（严格分层）

### A1｜先读正文，以可阅读性为中心（暂不读写手自评）

先完整通读，不在阅读中途逐项挑错。记录：最想跟随谁；读者第一次被抓住的位置；首次阅读动力下降的位置；高潮与情绪有没有兑现；最后一段留下了什么期待。**已知世界背景无法完全消除，但不能拿设定档案的内容替正文完成解释或情感铺垫。**

### A2｜文学六维评价（每维文字判断，不强制数字总分）

1. **阅读吸引力**：开篇、悬念、场景推进、章尾牵引。
2. **人物生命感**：人格通过选择、行动、私心与关系呈现，避免“优秀人才说明书”与刻意缺陷配额。
3. **戏剧因果**：目标、主要阻力、真正行动、结果或不可逆变化；不强制每个小场景都闭环，但本章必须有独特价值。
4. **节奏与信息负担**：历史、礼仪、经济、名册、官制是否掩盖了现场；说明是否可后置或改由人物冲突承载。
5. **文字、对话、POV 表现**：声音是否区分、语言是否自然、金句是否过密、观点是否替代人物；史体与小说文字各得其所。
6. **传奇与情感兑现**：英雄有可见功业、异兽／巫术有应有的实景冲击、危机与代价可感；在沉静章也看有没有令人难忘的情绪或发现，**不要每章都硬塞大高潮**。

提出质疑前说清楚**读者损失是什么**，并指向具体原文段落；不给抽象形容词堆砌。

### B｜独立 Canon 与连续性审计

文学判断单列，不与合规结果互相抵消。按出场内容**定向核对**年份、时序、身份、封君权限、地理交通耗时、官职、家庭关系、角色知道／不知道的事、物件状态、已定神异边界、POV、历史语言与旧设定回流；查证必须附**现行文件路径＋段落/标题或行号**。

区别三类：
- **硬冲突**：正文直接违反已确认 Canon／合同，须修；
- **未锁或待审创意**：正文新增场景细节，可能属于创作自由，先核对故事影响，不得自动判违规；
- **事实未验证**：当前未取得正文对应的来源／合同，必须标“待查”，不得假装已检查通过。

运行 `tools/canon_lint.py` 可以补充文件与元数据检查，但**不能替代全文文学评判，也不能用未运行的脚本伪称通过**。

### C｜形成单章审稿结论和定向修订指令

每个重要问题包含：严重度、**正文准确位置与短引文**、为何伤害读者／为何冲突 Canon、建议的修改方向、修改时必须保留的优秀元素。原则上只选最影响阅读的 **3—5 个优先修订问题**（真实硬冲突不受数量上限限制）。

对每章先写 **2—4 项必须保留的亮点**，防止写手修掉最好的段落。

### D｜复审

写作 Agent 提交新 `path@commit`；审稿模型优先针对上次 P0/P1 和 diff 复核，判定 **已解决／部分解决／引入新问题／作者选择保留**，只有新版本实质性变化才重新全章初读。不得每轮任意增加同一层级的偏好型优化项。

## 3. P0 / P1 / P2 定义及收尾规则

| 分级 | 定义 | 修稿规则 |
|---|---|---|
| **P0 必修** | 本章戏剧目标失败、中心人物明显失真、主要阅读链断裂、核心时序或关键 Canon 硬冲突 | 必须修复或提交作者裁决，不得以平均分冲抵 |
| **P1 建议优先修** | 明显拖沓、信息过载、情感不足、对白趋同、重大重复，但章节仍能成立 | 给局部或少量场景级修正方案；复审验证读者损失是否消失 |
| **P2 可选润色** | 局部措辞、标点、节奏和非必要意象 | 不阻断定稿，不升级成永无止境的返工 |

**停改标准**：无未解决 P0，主要读者损失已解决，剩余 P1 已向作者说明并可接受，P2 不阻断。作者确认后方可 lock。审稿模型默认**只读、不代写整章、不改 Canon、不改物理锁**。

## 4. 防止审核本身造成五项核心风险

- **过度设计**：不提议额外增国、增官署、增派系来“增强真实感”，除非正文有无法解决的硬因果缺口。
- **理想化人物**：鼓励自然的人性细节与真正的情绪，但不得机械要求每位英雄犯错／黑化或反派洗白。
- **信息过载**：标示历史解释阻塞阅读的起止段，优先提删减、分散、变为动作；不是写另一份设定说明。
- **POV/群像失焦**：看单主视角内外、其他人物有无行动辨识度，及跨章情感接力；不得为平均戏份强增新 POV。
- **无限反复修订**：审稿人不能用空泛的“再优化”阻止验收，凡 P0/P1 应具备具体证据、修复方向及可检验的结束条件。

## 6. 报告交付

严格使用 `review/templates/Chapter_Review_Report_Template_V1.0.md`，但避免只写表格而没有可读的专业判断。

默认在 ChatGPT 对话展示。若作者要求 Git 留档，审稿报告放 `work/audits/literary/`，命名中保留**逻辑章号、正文版本、所审 commit**；报告本身是评估意见、**永不成为新的 Canon owner**。未经请求不得直接改写写作 Agent 的正文。

**注**：对于不能直接观察的“陌生读者真实偏好”，只能给基于文本的预测性判断，不能冒称进行了读者访谈。
